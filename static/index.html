Notification grouping (dedup)

When enabled, klaxond buffers inbound events per source for the configured window before delivering a single aggregated notification. Useful when a cluster-wide trigger (e.g. WUD finding the same image update on N hosts) would otherwise produce N pushes.

Strategy key groups events sharing the same dedup key: WUD → image name, Grafana → alertname, Beszel → container name, HC → check name.
Severity caveat: by default critical events are NOT debounced (delivered immediately, even if buffering is enabled). Use the override critical toggle per source if you want to debounce critical too. Disk-backed pending queue at /data/dedup_pending/ survives klaxond restarts — pending events are flushed immediately on next start.

Pending counts shown in cards are live (refreshed when this tab is opened).
