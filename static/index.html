Inhibition rules (persisted to klaxond.toml)

  

    Source-agnostic (0.9.6+): rules apply to all 5 emitters by default. Restrict scope by selecting one or more sources under Applies to (empty = all). Match type is exclusive — pick one:
    match_by (equality on one label vs. source anchor),
    match_label + regex (regex on one label),
    or match_all (suppress everything).
    Saving replaces the in-memory rules and clears any active suppressions — they re-arm naturally on the next source alert.

Maintenance windows (scheduled silences, 0.9.19+)

  

    Cron-driven silences. When an alert arrives during a window AND its labels match the rule's match dict (subset-equality), the alert is suppressed with channel scheduled-mute and the schedule name as suppressed_by. Use for backup windows, planned maintenance, recurring noise sources.
    
Cron is standard 5-field (min hour dom month dow). Duration in minutes from cron-tick. Applies-to empty = all sources.

ntfy topics

  

    

      Each topic has a name (ntfy topic id), an optional bearer token, and a list
      of severities it handles. Same severity in multiple topics → fan-out
      (notification sent to all matching topics). Severity names can be any
      non-empty string (e.g. info, warning,
      critical, or custom like low/page).
      
Token ***SET*** = keep existing; empty = clear (env vars
      repopulate at next reload for legacy info/warning/critical names).

Inbound webhook auth (0.9.18+, per-source shared secret)

  

    

      Optional shared secret per ingest source. When configured, the emitter MUST present the secret via one of:
      
1. Authorization: Bearer <secret> header (Grafana Alertmanager, ntfy, custom)
      
2. X-Klaxond-Token: <secret> header
      
3. ?token=<secret> query parameter
      
Sources with no configured secret remain in legacy permissive mode (accept all — same as ≤ 0.9.17). Env KLAXOND_INGEST_SECRET_<SOURCE> overrides TOML.
    

    

      
SourceStatusSource of secretActions

      
    

    
"Generate" creates a 64-char hex secret server-side; the value is shown once in a toast — copy it into the emitter immediately. "Clear" removes the secret (source returns to permissive mode).

Delivery — policies + rules

  
Policies define how klaxond delivers an alert (cascade = stop at first OK; broadcast = fire all tiers in parallel). Rules pick a policy based on the alert's labels (first-match wins, regex with re: prefix). When no rule matches the default policy applies. cascade is the synthetic policy built from the global [cascade] tier list in klaxond.toml — picked here by name.

Notification grouping (dedup)

  

    When enabled, klaxond buffers inbound events per source for the configured
    window before delivering a single aggregated notification. Useful when a
    cluster-wide trigger (e.g. WUD finding the same image update on N hosts)
    would otherwise produce N pushes.
  

  

    Strategy key groups events sharing the same dedup key:
    WUD → image name, Grafana → alertname, Beszel → container name, HC → check name.
    

    Severity caveat: by default critical events are NOT debounced
    (delivered immediately, even if buffering is enabled). Use the
    override critical toggle per source if you want to debounce critical too.
    Disk-backed pending queue at /data/dedup_pending/ survives klaxond
    restarts — pending events are flushed immediately on next start.
  

  

  

    
    
  

  
Pending counts shown in cards are live (refreshed when this tab is opened).
